# Workspace tabs and command palette

Every implemented destination starts open on first use. Opening an existing destination focuses its existing tab. Explicitly closed tabs stay closed across reload, newly introduced destinations are offered automatically, and Open every tab reopens available destinations. Overview starts pinned; a pinned tab must be unpinned before closing, and one tab remains open so navigation never disappears.

The New tab catalog searches actual implemented destinations, settings and workflow controls. Unsupported states have explicit reasons, such as registering a passkey before changing password sign-in. The command palette opens from the header or Ctrl+Shift+F and routes to the real control, including its normal confirmations. Theme, language and motion controls inside the palette apply and persist through the same settings consumer.

Tabs support arrow keys, Home/End, accessible selection state, close/pin controls and a horizontally scrollable narrow layout. Machine drafts are saved when navigating away. The catalog's search is independent from machine search and uses plain text. Full regex construction, advanced tab grouping/reordering and destinations belonging to unfinished design boards remain pending; this catalog does not present those as implemented.

## Search and the regular expression builder

The search box in the header filters machines by name, notes, folder, tags and architecture. The **.\*** button beside it switches to regular expression search and opens a builder under the header: flags (ignore case, multiline, dot matches newline), which fields are searched, insert buttons for common tokens (digit, word, space, any, repeats, alternatives, anchors, groups and sets) and a status line that says how many machines match or why a pattern is not valid. Patterns are limited to 200 characters, an invalid pattern filters nothing out silently, and the choice is remembered in this browser. `scripts/verify-search.mjs` checks this in headless Edge (evidence/search).

The builder also has five tool tabs, all using the JavaScript (ECMAScript) regular expression flavour of the browser:

- **Explain** lists each part of the pattern in order with what it means, indented by group depth: anchors, classes and sets, escapes (including hex and Unicode), quantifiers (greedy or lazy), numbered and named groups, look-ahead and look-behind, and back-references. Explanations are in English and Cantonese.
- **Test** runs the pattern over sample text, which starts as one line per machine and can be edited. Matches are highlighted, and a table lists each match with its position and its numbered and named groups. At most 1,000 matches are listed.
- **Replace** previews the result of a replacement (`$1`, `$<name>`, `$&`). Nothing is changed.
- **Split** shows the parts the sample breaks into at each match.
- **Library** saves the current pattern and flags under a name in this browser, then reuses or deletes it. A pattern that does not compile is not saved.
- **Debug** steps through how the pattern is matched against the sample: each attempt at a new start position, each part tried, whether it matched or failed, and each time the engine backs up to try another way. First, previous, next, last and a step slider move through the steps, with the current position shown as a caret in the text and the current part highlighted in the pattern. It uses a small step-recording matcher that follows the same order as the browser's engine; tests check that it finds the same match and groups as the browser on 16 patterns. It stops after 200,000 steps and shows the first 3,000. It does not step through look-behind or Unicode property escapes and says so; the Test tab still runs those.
- **Other flavours** compares the pattern with PCRE, Python `re`, .NET, Java and Go (RE2): whether it works as written, works with differences, or does not work, with the reason (for example, Go has no look-around or back-references, Python needs `(?P<name>…)` and fixed-length look-behind, and `$` also matches before a final line break outside JavaScript). For Python it shows the converted pattern.
- **Code** generates code that compiles the pattern with its flags and lists every match, in JavaScript, Python, C#, PowerShell, Java or Go, with a copy button. Quotes and slashes are escaped for each language.
- **Search files** searches up to 20 local text files of at most 2 MiB each, line by line, and lists the matching lines with their line numbers. Files are read in the browser only and never sent to the server. The search stops after three seconds and lists at most 500 lines. With **Replace in files** on, it shows how many replacements each file gets and each changed line before and after, and offers a download of each changed copy (or all of them). The chosen files themselves are never changed: the browser only has a copy of them.

Test, Replace and Split run in a background worker that is stopped after one second, so a pattern that backtracks badly, such as `(a+)+$` on a long run of `a` followed by `!`, reports that it was stopped instead of freezing the page. The machine filter itself runs on short machine fields on the page. The debugger and file search also run in that worker, with a three-second limit. The flavour tab reports known differences from other engines; it does not run PCRE, Python, .NET, Java or Go themselves, because that would mean shipping those runtimes to the browser or having the server run interpreters on patterns typed in the browser. `scripts/verify-regex-tools.mjs` checks every tab, the time limits, the library across a reload, the debugger's steps, local file search without upload, and the new tabs in Cantonese at 375 pixels in headless Edge (evidence/regex-tools).

### Searching beyond machines

The same search, plain or regular expression with its flags, also looks through disk images (by name, machine and format), ISO images and the help articles. Matches appear under the machine results in an **Also found** panel, with the matching part highlighted in the field where it was found and a short snippet for article text. Choosing a disk or ISO opens Storage; choosing an article opens Help and moves focus to that article. Storage is loaded when it is first needed. `scripts/verify-search-everywhere.mjs` checks this in headless Edge (evidence/search-everywhere).

### Command palette search

The command palette has its own search, separate from the header search, with its own **.\*** switch. With it on, the palette offers the same flags (ignore case, multiline, dot matches newline, Unicode), token buttons, a status line with the number of matches or the reason a pattern is not valid, and the part-by-part explanation. The label and the description of each command are matched separately, so `^` and `$` anchor to either. The palette's choices are remembered in this browser.

## Notifications center

Every notice that appears at the bottom of the screen is also kept in the notifications center, the bell in the header. Its badge shows how many are unread. The panel lists the last 50, newest first, with the time; closing it (Escape, the close button or a click elsewhere) marks them read and returns focus to the bell, **Mark all read** and **Clear** do what they say. The list is kept in this browser only. `scripts/verify-notifications.mjs` checks it in headless Edge (evidence/notifications).
